# API05 Broken Function Level Authorization /n 
## **BFLA:** _Perform an unauthorized function._ /n
BFLA happens when a user can access or perform functions that should only be available to a higher-privileged user.

### Impacts 
BFLA → Privilege escalation
1. Normal users perform admin functions.
2. Unauthorized data modification/deletion.
3. **Privilege escalation**.

### How to Test
I test Broken Function Level Authorization by checking whether a low-privileged user can access or execute functions that should only be available to higher-privileged users.

```
GET /api/user/profile
```
But an administrator has :
```
DELETE /api/users/123
GET /api/admin/reports
POST /api/admin/create-user
```
I authenticate as the **normal user**, identify privileged endpoints, and directly request them.

If the normal user can successfully execute:
```
DELETE /api/users/123
```
or access an admin function, despite not having the required role → **Broken Function Level Authorization**.

I test:

- Admin endpoints with a normal-user token
- Staff/manager functions with lower-privileged accounts
- HTTP method changes such as `GET → POST → PUT → DELETE`
- Hidden/unlinked API endpoints
- Both **read and write/administrative functions**

**Key distinction:**

- **BOLA** → Can I access **another object's data**?
- **BOPLA** → Can I access/modify **another object's property**?
- **BFLA** → Can I execute a **function/action I'm not authorized to use**?

I test BFLA by enumerating privileged functions and attempting to access or execute them using a lower-privileged user's session. If the server doesn't enforce role-based authorization, it's vulnerable.


### How to Prevent
BFLA → Function authorization
1. Enforce **role/function-level authorization** server-side.
2. Deny access by default and explicitly allow required functions.
3. Test authorization for every sensitive endpoint and HTTP method.
