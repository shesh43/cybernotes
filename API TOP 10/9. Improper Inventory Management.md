
**Inventory Management:** _Unmanaged or forgotten APIs remain exposed._
This happens when an organization doesn't properly track and manage its APIs, especially old, unused, or undocumented ones.

#### Impacts 
Inventory Management → Attack vulnerable/forgotten APIs
1. Attack old/vulnerable APIs.
2. Bypass security controls present in newer APIs.
3. Exposure of sensitive data or functionality.

#### How to Test
I test for Improper Inventory Management by identifying all API versions, endpoints, and environments that are exposed, and checking whether old, deprecated, or undocumented APIs are still accessible and properly secured.

I would check:

- **API versions** — `/api/v1`, `/api/v2`, `/api/v3`
- **Deprecated endpoints** that are still active
- **Development/staging APIs** exposed to the internet
- Undocumented or hidden endpoints
- Whether old API versions have **weaker authentication or authorization**
- Whether sensitive endpoints are unintentionally exposed
- Whether API documentation accurately reflects what is actually deployed
- Whether old versions receive proper security updates

**Example:**

Suppose the current API is:
```
POST /api/v2/users/change-email
```
But an old version is still available:
```
POST /api/v1/users/change-email
```
If `v1` has weaker authorization and allows a normal user to perform an action that `v2` correctly restricts, that's a potential **Improper Inventory Management** issue.

I compare documented and deployed APIs, enumerate versions and environments, and test whether deprecated, undocumented, or old endpoints remain accessible with weaker security controls.

#### How to Prevent 
Inventory → Know and manage all APIs
1. Maintain an accurate **API inventory**.
2. Remove/decommission old and unused API versions.
3. Secure and monitor development/staging APIs.
