# API02 Broken Authentication 
## **Authentication:** _Bypass or weaken user authentication._ 
Broken authentication happens when the application fails to properly verify a user's identity or manage their session.

### Impacts
Broken Authentication → Account takeover
1. Account takeover.
2. Unauthorized access to user data.
3. Impersonation of legitimate users.

### How to Test
I test for broken authentication by checking whether the application properly verifies a user’s identity and securely manages authentication sessions. I test login controls, password reset, MFA, session management, token handling, and account lockout mechanisms

Then I would test:
1. **Login**
    - Weak/default credentials
    - Username enumeration
    - Brute-force/rate-limit protection
    - Authentication bypass
2. **Session management**
    - Session ID/token predictability
    - Session fixation
    - Whether logout actually invalidates the session
    - Whether old sessions remain valid after password changes
3. **Password reset**
    - Predictable or reusable reset tokens
    - Token expiration
    - Whether reset tokens can be reused
    - Account takeover through the reset flow
4. **MFA**
    - MFA bypass
    - OTP reuse
    - OTP brute-force/rate limiting
    - Session/token issued before MFA is completed
5. **JWT/token authentication**
    - Improper signature validation
    - Expired tokens still being accepted
    - Weak token handling

Broken authentication occurs when an attacker can bypass or weaken the application's authentication or session controls and gain access as another user.

### How to prevent
1. Use strong authentication and secure password policies.
2. Protect sessions/tokens and invalidate them properly.
3. Implement  MFA, rate limiting, and secure password-reset mechanisms.
