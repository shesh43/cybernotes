**Resource Consumption:** _Consume excessive server resources._
This happens when an attacker can repeatedly or automatically abuse a sensitive business function without proper controls.

#### Impacts 
Resource Consumption → DoS / excessive resource usage
1. Application slowdown or **DoS**.
2. Excessive CPU, memory, bandwidth, or storage usage.
3. Increased infrastructure/cloud costs.

#### How to test 
I test for unrestricted resource consumption by identifying endpoints that consume significant server resources, such as login, search, file upload, report generation, password reset, or API requests. I then check whether the application properly limits how many requests, how much data, or how expensive an operation a user can perform

I would test:

- **Rate limits** → Can I send excessive requests without throttling?
- **Request size limits** → Can I submit excessively large inputs or files?
- **Pagination limits** → Can I request an extremely large number of records at once?
- **Expensive operations** → Can I repeatedly trigger resource-intensive operations?
- **Concurrency** → Can multiple simultaneous requests cause excessive resource usage?
- **Per-user/IP limits** → Are limits actually enforced per appropriate identity or source?

```
GET /api/products?limit=1000000
```
If the server processes and returns an extremely large dataset without enforcing a reasonable limit, that could indicate **unrestricted resource consumption**.


I test whether an unauthenticated or low-privileged user can consume excessive CPU, memory, bandwidth, storage, or application resources because the server lacks proper limits, quotas, or rate controls.


The key is: **don't just look for rate limiting—look for any missing control that allows disproportionate resource consumption.**


### How to prevent 
- Rate Limiting: Limit the number of requests a user can make within a specific time.
- Resource Limits: Set limits on request size, file uploads, execution time, and memory usage.
- Throttling: Restrict or slow down excessive requests to prevent server overload.
